# AX Job Agent - Development Rules

이 문서는 프로젝트를 진행하면서 정한 Notebook 작성 규칙, 코딩 규칙, 검증 규칙을 한곳에 모아 관리합니다.
새로운 규칙이 생기면 이 문서에 계속 추가합니다.

## 1. Notebook 기본 작업 단위

모든 Notebook 작업은 아래 3개 Cell을 **하나의 세트**로 진행합니다.

1. 작업 계획 — Markdown Cell
   - 이번 작업에서 무엇을 할지
   - 왜 이 작업이 필요한지
   - 확인할 항목, 하지 않을 것, 완료 조건
2. 실제 코드 — Code Cell
   - 현재 작업에 필요한 코드만 작성
   - 확인 출력(shape, 결측, 중복 등)도 이 Cell 안에서 함께 수행
   - 초보자가 이해할 수 있도록 간단한 주석 사용
3. 실행 결과 해석 / 분석 / 요약 — Markdown Cell
   - 실제 실행 결과가 무엇을 의미하는지
   - 예상과 다른 부분
   - 다음 단계로 넘어가도 되는지
   - 필요하면 추가 확인 사항

```text
작업 계획 (Markdown)
↓
실제 코드 (Code)
↓
실행 결과 해석 / 분석 / 요약 (Markdown)
```

- 새 셀 세트는 Notebook 마지막에 추가하고, 이미 검증된 기존 셀은 수정하지 않는다.
- 새 셀 제목에는 원래 공식 STEP 번호(STEP 09, STEP 10 …)를 사용한다.

## 2. Notebook 코드 원칙

- 한 Cell에 너무 많은 작업을 넣지 않는다.
- Python 초보자가 읽을 수 있는 크기로 작성한다.
- 코드 실행 결과를 직접 확인할 수 있게 출력한다.
- 코드만 작성하고 다음 STEP으로 넘어가지 않는다.
- 앞 단계 변수가 필요한 Cell은 먼저 변수가 있는지 확인하고, 없으면 안내 메시지를 출력한다. (데이터를 임의로 만들지 않는다)
- 외부 요청이 있는 Cell(예: STEP 03, 07-A)은 전체 재실행 대신 필요한 Cell만 선택 실행한다.

## 3. 데이터 검증 원칙

- shape 확인
- 컬럼 확인
- 결측 확인
- 중복 확인
- 날짜 변환 확인
- 원본 DataFrame을 가능한 보존
- 새로운 결과는 별도 변수/DataFrame에 저장 (예: `df_real_jobs` → `df_unique_jobs` → `df_filtered_jobs`)
- 값을 임의로 만들어 넣지 않는다. 찾지 못한 값은 `None`으로 둔다.
- 표본이 작을 때는 "현재 수집된 N건 기준"으로만 해석하고, 시장 전체 경향으로 일반화하지 않는다.

## 4. 외부 요청 원칙

- 요청 횟수를 최소화
- 우회/회피 로직 사용 금지 (CAPTCHA 우회, 프록시/IP 변경, 반복 재시도 등)
- HTTP 200만 보고 성공 판단 금지
- 실제 응답 내용 확인 (title, 본문 문자열 등)
- 처음부터 대량 수집하지 않는다. (검색어 1개 → 페이지 1개 → 소량 공고 순서로 확장)

## 5. API Key 규칙

- 코드에 직접 작성 금지
- .env 사용
- 키 값 출력 금지 (키 일부, 키 길이 포함 — "설정됨 / 미설정"만 출력)
- .env Git 추적 금지 (`.gitignore`에 `.env` 포함, `.env.example`만 Git에 포함)
- 오류 메시지를 출력할 때 키가 섞여 있을 가능성에 주의한다.

## 6. STEP 진행 규칙

- 한 번에 공식 STEP 하나만 진행
- 실행 → Human Verification → DONE
- 완료 전 다음 STEP 진행 금지
- 진행 상태는 `docs/PROGRESS.md`에 기록하고, 사용자가 결과를 확인하기 전에는 DONE으로 바꾸지 않는다.

## 7. 추가 예정 규칙

필요해지면 아래 항목을 이 문서에 추가합니다.

- 변수명 규칙
- 파일/폴더명 규칙
- 함수 작성 규칙
- 예외 처리 규칙
- 로그 출력 규칙
- Agent에게 코드 수정을 맡길 때의 규칙
